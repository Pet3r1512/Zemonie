# Zemonie — Development Guidelines

Zemonie is a Gen Z–focused money management app. It is a **pnpm monorepo** with two
workspaces:

- `client/` — React SPA (Vite + TanStack Router + Tailwind v4), deployed to Cloudflare Workers.
- `server/` — Hono + tRPC API (Prisma + Neon PostgreSQL), deployed to Cloudflare Workers.

Read `PROJECT_STRUCTURE.md` for a full map of the codebase before making changes.

---

## Notes for AI Agents

- **Always use `pnpm`** — never `npm` or `yarn`. The repo is a pnpm workspace.
- **Run commands per workspace** with `pnpm --dir client <cmd>` or `pnpm --dir server <cmd>`
  (or `pnpm --filter client <cmd>`). The root `dev` script runs both via `concurrently`.
- **Do not edit generated files.** `client/src/routeTree.gen.ts` is auto-generated by the
  TanStack Router plugin — it is excluded from lint/format and must not be hand-edited.
- **Never commit secrets.** `.env`, `.env.local`, and `server/.dev.vars` are git-ignored.
  Do not add credentials, tokens, or connection strings to tracked files.
- **Use the `@/` path alias** for imports within each workspace (maps to that workspace's
  `src/`). Prefer it over long relative paths.
- **Match existing conventions.** Mirror nearby files for structure, naming, and patterns
  rather than introducing new ones.
- **Scope changes to the ticket.** Keep diffs focused; avoid unrelated refactors or
  dependency bumps unless that is the task.
- **Verify before finishing**: type-check, lint, format, and run relevant tests (see below).
- **Only commit, push, or open PRs when explicitly asked.**

## Branching Model

- Branch off `master`. Keep branches short-lived and focused on one ticket.
- **Branch name format:** `<type>/<kebab-case-description>/<TICKET-ID>`
  - Examples: `fix/email-verify-dialog-UI/FIX-056`,
    `feature/edit-budget/FEAT-069`,
    `test/about-us-page-components/TEST-020`,
    `documentation/docs-for-ai/DOC-009`.
- **Common types / ticket prefixes:**
  - `feature/` → `FEAT-###`
  - `fix/` → `FIX-###`
  - `improvement/` → `IMP-###`
  - `test/` → `TEST-###`
  - `documentation/` → `DOC-###`
  - ops / infra → `OPS-###`
  - `release/` → `release/vX.Y.Z`
  - urgent production fixes → `HOTFIX/...`
- **Commit messages:** `#TICKET-ID: Short description` (e.g. `#FIX-056: Email verify dialog UI`).
  Release commits use `Release/vX.Y.Z`.
- **Pull requests:** target `master`, titled like the commit convention
  (`#TICKET-ID: Description`), and are squash-merged with the PR number appended
  (e.g. `#FEAT-069: Edit budget (#323)`).
- Before opening a PR, make sure type-check, lint, format, and tests pass.

## Package Management

- **Tool:** `pnpm` with workspaces declared in `pnpm-workspace.yaml` (`client`, `server`).
- `pnpm-workspace.yaml` enforces supply-chain safety: `minimumReleaseAge` (new releases must
  age before install) and `trustPolicy.no-downgrade`. Do not weaken these.
- Install from the repo root: `pnpm install`.
- Add a dependency to a specific workspace:
  `pnpm --dir client add <pkg>` / `pnpm --dir server add <pkg>`.
- Commit `pnpm-lock.yaml` changes that result from dependency updates. The lockfile is
  excluded from formatting.
- **Node:** CI runs on Node 22 — use a compatible version locally.

## Code Quality

- **Linter:** [oxlint](https://oxc.rs) configured in root `.oxlintrc.json`.
  - Plugins: `typescript`, `unicorn`, `oxc`, `react`, `react-perf`.
  - Categories: `correctness` = **error**, `suspicious` = **warn**.
  - Ignores: `dist`, `build`, `coverage`, `.wrangler`, `node_modules`,
    `client/src/routeTree.gen.ts`.
- The client additionally uses an ESLint flat config (`client/eslint.config.js`) for
  React Hooks, React Refresh, and Storybook rules.
- **Commands (root):**
  - `pnpm lint` — check.
  - `pnpm lint:fix` — auto-fix.
- Keep functions small and typed; prefer early returns; avoid unused locals/params
  (enforced by TypeScript — see below).

## Testing

- **Runner:** [Vitest](https://vitest.dev) — React Testing Library in `client/`,
  plain Vitest (`environment: "node"`) in `server/`.
- **Environment (client):** `jsdom`; global setup in `client/setupTests.ts`
  (`@testing-library/jest-dom` + a `ResizeObserver` polyfill). Globals are enabled.
- **Environment (server):** `node`; `server/vitest.setup.ts` injects an ephemeral
  `ENCRYPTION_KEY` for the test run so no key-shaped secret is ever committed.
- **Location:** co-locate tests next to the source as `*.test.tsx` / `*.test.ts`.
- **Browser/Storybook tests:** `client/vitest.workspace.ts` defines Storybook browser
  projects (`chromium`, `firefox`, `webkit`) via Playwright + `@storybook/addon-vitest`.
  CI runs these against a running Storybook (`STORYBOOK_URL`).
- **Mocking conventions:** use `vi.mock(...)` for API client functions, `sonner` (`toast`),
  TanStack Query (`useMutation`), and TanStack Router (`Link`, `useRouter`). See
  `client/src/components/Auth/SignUp/SignUpForm.test.tsx` for the reference pattern.
- **Query/assert** with `screen.getByRole` / `getByText` / `getByTestId`, drive interactions
  with `userEvent`, and await async UI with `waitFor`.
- **Commands:**
  - `pnpm --dir client test` (or root `pnpm test:client`) — run the client suite.
  - `pnpm --dir client test-watch` — client watch mode.
  - `pnpm --dir client coverage` — coverage (istanbul provider).
  - `pnpm --dir server test` (or root `pnpm test:server`) — run the server suite
    (`vitest run`); `pnpm --dir server test-watch` for watch mode.
- **CI:** `.github/workflows/ci.yaml` type-checks and tests the server (`pnpm test:server`),
  then runs the client tests (across Chromium, Firefox, WebKit) and builds, on every PR
  and push to `master`.

## Formatting & Type Checking

- **Formatter:** [oxfmt](https://oxc.rs) configured in root `.oxfmtrc.json`
  (ignores `dist/`, `build/`, `coverage/`, `.wrangler/`, `pnpm-lock.yaml`,
  `client/src/routeTree.gen.ts`).
  - `pnpm format` — check.
  - `pnpm format:fix` — write.
- **Type checking:** strict TypeScript in every workspace.
  - Client (`client/tsconfig.app.json`): `strict`, `noUnusedLocals`,
    `noUnusedParameters`, `noFallthroughCasesInSwitch`, `noEmit`.
  - Server (`server/tsconfig.json`): `strict`.
  - Run client type-check: `pnpm --filter client exec tsc --noEmit`.
- **Git hooks (Husky):**
  - `pre-commit`: `pnpm format:fix && pnpm lint-staged`
    (lint-staged runs `oxlint --fix` + `oxfmt` on staged files).
  - `pre-push`: `pnpm lint-prepush` → `tsc --noEmit` (client) **and** `oxlint`.
  - Do not bypass hooks (`--no-verify`) unless explicitly instructed.

## Exception Handling

Follow the established patterns on each side of the stack.

### Server (tRPC / Hono)

- Throw `TRPCError` with an appropriate `code` for expected API failures:
  ```ts
  if (!original) throw new TRPCError({ code: "NOT_FOUND" });
  // auth guard:
  throw new TRPCError({ code: "UNAUTHORIZED" });
  ```
- Throw a plain `Error` for programmer/config errors (e.g. missing env):
  ```ts
  if (!url) throw new Error("DATABASE_URL is not defined");
  ```
- Validate all procedure inputs with **Zod** so invalid data fails before business logic.

### Client (API wrappers)

- `fetch`-based wrappers: check `response.ok` and throw a message-bearing `Error`:
  ```ts
  const res = await response.json();
  if (!response.ok) {
    throw new Error(res.error?.message ?? "Unknown Error");
  }
  ```
- Better-Auth client calls return `{ data, error }` — throw on `error` with a fallback:
  ```ts
  const { data, error } = await authClient.signIn.email({ email, password });
  if (error) throw new Error(error.message || "Sign in failed");
  return data;
  ```

### Client (UI / data mutations)

- Surface errors to users via TanStack Query `onError` + `sonner` toasts; keep the form
  mounted so the user can retry:
  ```ts
  useMutation({
    mutationFn,
    onError: (error) => toast.error(error?.message ?? "Something went wrong"),
    onSuccess: () => toast.success("Done!"),
  });
  ```
- Prefer user-friendly, specific messages over raw error strings where a known error code
  maps to a clear explanation.
